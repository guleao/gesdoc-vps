### Arquitetura do cofre

`/opt/gesdoc/.sops.yaml` define uma regra e **um destinatário age distinto por ambiente**:

```yaml
creation_rules:
  - path_regex: infra/secrets/hml\.enc\.env$
    age: age18utxnl6mk8x7k9vvpr0a9f5msdaah03ems0rdln0g5rdavwqn40q9p49y9
  - path_regex: infra/secrets/prd\.enc\.env$
    age: age1p9jrzs8s5hae3xfep6y6nfcfnh8dclef0y5t4z5qujc08qj4040sjdthhk
```

> Chave separada por ambiente é a decisão mais acertada deste desenho. Quem tem a chave de homologação **não consegue** decifrar os segredos de produção. A maioria das implementações de SOPS usa uma chave única para tudo e perde essa separação.

|---|---|---|

### Padrão de leitura pelos serviços

É a parte que normalmente fica mal resolvida, e aqui está correta. `infra/up.sh`:

```bash
exec sops exec-env "infra/secrets/${ENV}.enc.env" \
  "docker compose -f infra/compose.${ENV}.yml $*"
```

`sops exec-env` decifra **em memória** e injeta as variáveis no ambiente do processo filho. Consequências:

- Nenhum `.env` em texto plano é escrito em disco, em nenhum momento
- Os segredos não aparecem em `docker inspect` como arquivo montado
- Não há janela em que um arquivo decifrado exista e possa ser lido por outro processo

Os compose files consomem as variáveis com **fail-fast**:

```yaml
POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?defina no cofre de segredos}
```

A sintaxe `${VAR:?mensagem}` aborta o `docker compose` se a variável não existir, em vez de subir o container com senha vazia. Detalhe pequeno, efeito grande.

### Por que o volume do n8n entra junto

`export:credentials` roda **sem** `--decrypted`: as credenciais saem cifradas, como estão no banco, para que o backup não carregue segredos em texto plano. A chave que as decifra (`N8N_ENCRYPTION_KEY`) vive em `/home/node/.n8n/config`, dentro do volume.

Restaurar o banco sem o volume devolve credenciais ilegíveis. Os dois arquivos são um par e precisam ser guardados juntos.

### Validação em dois estágios

Cada arquivo passa por duas checagens antes de ser aceito:

1. `gzip -t` — integridade do compactado
2. **tamanho mínimo** — um dump truncado permanece gzip-válido até o ponto do corte, então o teste de integridade sozinho não detecta esse caso

Falhando qualquer um, o `.tmp` é descartado e o script aborta com `ERRO`, preservando o backup bom do dia anterior.

### Cópia externa — Cloudflare R2

`backup-offsite.sh` é invocado por `sops exec-env`, que injeta as credenciais do R2 **em memória**. O remoto do rclone é montado por variáveis `RCLONE_CONFIG_R2_*`: não existe `rclone.conf` com credencial em disco, em nenhum momento.

No remoto, duas operações explícitas:

- `rclone copy` — nunca remove nada por diferença de origem
- `rclone delete --min-age 30d` — limpeza só por idade

**Estado: pendente de credencial.** A regra `infra/secrets/backup.enc.env` já está em `.sops.yaml` e o `rclone` 1.60.1 está instalado. Falta criar o bucket e o token no painel da Cloudflare — passo a passo em `docs/BACKUP.md`. Até lá o script conclui o backup local normalmente e registra `AVISO cópia externa NÃO configurada`.

### Teste de execução

### 🟡 F-5 · `sshd_config` com diretivas duplicadas e conflitantes

**Severidade:** Média

O valor efetivo hoje está **correto** (`sshd -T` confirma `passwordauthentication no`), porque o OpenSSH adota a **primeira** ocorrência de cada diretiva e o `Include` fica no topo do arquivo principal. # consolidar num só (ex. 99-hardening.conf) e remover as linhas duplicadas
```bash
sudo sshd -t                                        # validar ANTES de reiniciar
sudo systemctl reload ssh
```

### ✅ F-10 · Sem swap — **RESOLVIDO 2026-10-02**

**Severidade:** Baixa

Mas sem swap um pico de memória resulta em **OOM kill imediato** em vez de degradação gradual — o kernel mata o maior processo, que aqui seria o n8n (324 MB) ou um Postgres. **Correção** (opcional, 2 GB é suficiente como almofada):

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
sudo sysctl -w vm.swappiness=10   # só usa swap sob pressão real
```

```bash
sops -d secrets.enc.env | diff - .env && echo "cifragem conferida"

# 3. criar o wrapper, no mesmo padrão do up.sh do gesdoc
printf '%s\n' '#!/usr/bin/env bash' 'set -euo pipefail' \
  'cd "$(dirname "$0")"' \
  'exec sops exec-env secrets.enc.env "docker compose $*"' > up.sh
chmod +x up.sh

# 4. só depois do passo 2 passar, remover os textos planos
shred -u .env .env.bak-fila
```

Ordem importa: **nunca** apague o `.env` antes do `diff` do passo 2 confirmar. E faça uma stack por vez, validando que os containers sobem, antes de passar à próxima.

Prioridade sugerida: `cloudflared` primeiro (o `TUNNEL_TOKEN` tem o maior raio de impacto), depois `n8n`, por último `postgresql-olpf`.

> Esta migração **recria containers de produção**. Não a executei justamente por isso — é uma alteração com janela de indisponibilidade, não uma leitura.

## 18. O que já está bem feito

Vale registrar, porque é bastante coisa e a tendência é só olhar os problemas:

- **Superfície de ataque praticamente nula.** UFW em deny-all com exceção única do `tailscale0`; SSH inalcançável pela internet; ingress por túnel Cloudflare sem porta de entrada. O contador de 1 falha de autenticação no `auth.log` é a prova empírica.
- **SSH endurecido:** sem root, sem senha, sem keyboard-interactive, `AllowUsers` restritivo, `MaxAuthTries 3`.
- **Defesa em profundidade real:** fail2ban + auditd + AppArmor (23 perfis em enforce) + Lynis agendado. É raro ver os quatro juntos.
- **Script de backup escrito com cuidado:** `set -euo pipefail`, `umask 077`, escrita em `.tmp` com `gzip -t` antes do `mv`, retenção automática. 7 dias consecutivos sem falha.
- **Host enxuto.** Nenhum runtime de aplicação instalado fora de container. Superfície mínima, patching simples.
- **Bancos corretamente isolados:** nenhum Postgres ou Redis acessível de fora; bind em `127.0.0.1` quando publicado.
- **Higiene de Docker automatizada:** prune de imagens e build cache em cron, com jitter. Resultado: 0 B reclaimable.
- **Redis com `noeviction`** — escolha certa para carga de fila, prefere falhar a perder job.
- **Cofre de segredos corretamente implementado** (§11): SOPS + age com chave separada por ambiente, `sops exec-env` injetando em memória sem tocar o disco, `${VAR:?}` com fail-fast nos compose, `.gitignore` com lista de exceções certa. É uma implementação melhor que a média do mercado — o problema não é o desenho, é a chave não ter cópia (F-14).
- **Zero unidades systemd falhadas, zero OOM kills, zero erros de I/O.**

### Decisão deliberada: senha do root não foi travada

A recomendação original em F-3 incluía `passwd -l root`. Não apliquei, e mudo a recomendação: travar a senha do root remove o único caminho de recuperação pelo **console VNC** do provedor. Se o `sudo` quebrar — pacote corrompido, `sudoers` inválido, filesystem em read-only — o login de root no console é o que resta. Num VPS sem acesso físico, manter essa porta vale mais que o ganho marginal de travá-la, já que `PermitRootLogin no` e `AllowUsers augusto` já bloqueiam root por rede.

Vale trocar a senha do root por uma forte e guardá-la no mesmo gerenciador da chave age (F-14).
